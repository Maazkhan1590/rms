RMS Plan vs. Status Report

Overall plan, completed work, and pending items
Project: Research Management System (RMS)
Report Date: February 10, 2026
Summary Status: Core features completed

Executive Summary

The core RMS plan has been implemented: database schema, scoring engine, workflow system, evidence files, admin portal, and faculty submissions for publications, grants, RTN, and bonus recognition are all in place and working together.

Remaining work is focused mainly on reporting/analytics extensions, export refinements, faculty profile, and additional validation/testing and polish – these are incremental, not structural, changes.

Plan vs. Implementation Status by Phase

Plan Item / Phase Status Notes (Evidence / Details)
Phase 1: Database schema (policies, workflows, evidence, publications, grants, RTN/bonus, audit) Completed
  • Database tables created for policies, policy versions, rules, workflows, approvals, evidence files, publications, grants, RTN submissions, bonus recognitions, and audit logs.
  • All foreign key relationships and basic indexes are defined to support reporting and workflow queries.
  • Schema reflects the latest agreed‑upon scoring and workflow model used throughout the system.
Phase 2: Models & core services (ScoringService, WorkflowService, FileUploadService, PolicyService, ReportService) Completed
  • Eloquent models added for all core entities (publications, grants, RTN, bonus, evidence, workflows, approvals, policies).
  • ScoringService encapsulates calculation logic for all activity types with caps and policy‑based weights.
  • WorkflowService centralises state transitions, role checks, comments, and approval history.
  • FileUploadService standardises validation, storage paths, and metadata for evidence files.
  • PolicyService and ReportService expose reusable methods used across controllers and views.
Phase 3: Admin portal (layout, dashboard, policies, publications, grants, workflows, users, reports) Completed
  • Admin layout created with navigation for policies, publications, grants, RTN, bonus, workflows, users, and reports.
  • Dashboards implemented with charts, statistics cards, and recent activity feeds.
  • List screens use DataTable‑style components with search, filters, pagination, and bulk actions where relevant.
  • Admin can manage master data (policies, workflow definitions, some configuration values) from the UI.
Phase 4.1–4.4: Faculty portal layout, dashboard, publication submission flows In progress
  • Faculty layout implemented with menu entries for publications, grants, RTN, bonus and related areas.
  • Publication submission forms allow create/edit, evidence upload, and tracking of workflow status.
  • Faculty can view their own submissions, filter by status, and open details for each item.
  • Further work planned on faculty dashboard metrics, shortcuts, and contextual guidance text.
Phase 4.5: Faculty grant submission Completed
  • Grant submission forms implemented with fields for type, title, agency, amount, duration, role, and co‑investigators.
  • Evidence file upload integrated (award letters, contracts, approvals, etc.).
  • Submissions automatically enter the unified workflow for coordinator/dean review and approval.
  • Approved grants are scored and included in reporting and dashboards.
Phase 4.6: Faculty RTN & bonus recognition submission Completed
  • RTN‑3 (student co‑authors) and RTN‑4 (course file updates) forms implemented with structured fields and evidence uploads.
  • Bonus recognition forms implemented for multiple recognition types with metadata and supporting documents.
  • Both RTN and bonus submissions use the same workflow and scoring services as publications and grants.
  • Faculty can monitor the status of RTN and bonus submissions from their portal.
Phase 4.7: Faculty profile Pending
  • No dedicated faculty profile screens are exposed yet in the portal.
  • Profile fields are partially present in the database/user model and will be surfaced via new UI.
  • Planned work is captured under the roadmap section “Faculty profile module”.
Phase 4.8: Public/faculty publication browsing Completed
  • Public‑facing publication list and detail pages implemented with basic filters.
  • Faculty can browse their own publications and see workflow/scoring status where applicable.
  • Views are wired into the same models, scoring, and workflow structures used by admin screens.
Phase 5: Approval workflow system (states, roles, history) Completed
  • Standard workflow states defined and shared across all modules (Draft, Submitted, Under Review, Approved, Returned, Rejected).
  • Role‑based transitions implemented to ensure only authorised users can approve, reject, or return items.
  • Approval history stored with timestamps, actors, comments, and previous/new states.
  • Fallback routing implemented when certain approver roles (e.g., coordinator) are not assigned.
Phase 6: Dynamic scoring engine Completed
  • Scoring policies and rules modelled to support multiple activity types with configurable weights and caps.
  • Scoring integrated into submission flows so that approved items are automatically included in totals.
  • Scores aggregated per faculty member and surfaced in reporting and dashboards.
Phase 7: File upload & evidence management Completed
  • Polymorphic evidence file model implemented so multiple files can be attached to any submission.
  • Support for several file categories (acceptance letters, certificates, appointment letters, etc.).
  • Validation added for file size and type; files stored using stable, secure paths.
  • Admin views allow verification and review of uploaded evidence.
Phase 8: Reporting system (CV, summaries, dashboards, exports) In progress
  • Core admin dashboards implemented with charts for submissions and module‑level statistics.
  • Basic exports (Excel/PDF) available for key tables via DataTable and backend helpers.
  • Additional management analytics, CV‑style reports, and refined templates are planned in the roadmap.
Phase 9: Routes, roles & middleware Completed
  • Routes organised by area (admin, faculty, public) with clear prefixes and middleware assignments.
  • Role‑based access control enforced so each user type only sees relevant menus and actions.
  • Redirects and guards adjusted to prevent loops and ensure correct landing pages.
Phase 10: Validation, testing & UI polish In progress
  • FormRequest‑based validation implemented for several critical forms (e.g., publications, grants).
  • Main submission and approval paths have been manually tested and verified.
  • Further automated tests, broader validation rules, and cosmetic/UI refinements are planned as part of the 5‑month roadmap.

Completed Scope (Overview)

  • End‑to‑end submissions and approvals for publications, grants, RTN, and bonus recognition.
  • Unified workflow engine with multi‑level approvals and audit trail.
  • Dynamic scoring engine based on configurable policies and rules.
  • Multiple evidence file uploads with verification and secure storage.
  • Admin portal with dashboards, charts, filters, and export features.
  • Faculty portal for submitting and tracking research outputs and activities.

Pending / Next Priority Items

Remaining work focuses on refinement and institutionalisation of the system. These items can be delivered in a follow‑up phase without blocking current usage.

  • Faculty profile module: dedicated profile screens (view/edit), profile photo and CV upload, and integration of profile data into submissions and reports.
  • Advanced analytics dashboards: management overview charts, breakdowns by college/department/faculty, filters by period and activity type, and drill‑down to underlying submissions.
  • CV‑style exports and templates: standard CV layout per faculty member, mapping of all activity data, and refined PDF/Excel/Word export formats.
  • Validation, testing, and quality: additional field‑level validations, automated feature/regression tests, and basic performance testing for heavy listing and export actions.
  • UX / UI refinements: improved empty states and messages, consistent filters and actions across modules, and adjustments based on user feedback.
  • Performance and configuration: query/index optimisation, robust pagination for large datasets, and configuration screens for key master data and scoring parameters.
  • Security, audit, and documentation: final review of permissions, extended audit logging for sensitive actions, and user/technical documentation and training materials.
