RMS Progress – Grants, RTN & Bonus, Workflow Changes

Updated: February 3, 2026

Summary

This report focuses specifically on the status and technical details of the Grants, RTN (Return to Nature), and Bonus Recognition modules, and on the recent workflow changes that connect these modules to the approval engine.

  • End‑to‑end grant, RTN, and bonus flows are wired into the common workflow and scoring services.
  • Admin interfaces for reviewing, approving, and returning submissions are live.
  • Faculty‑facing submission screens for these modules are aligned with publication flows (where implemented).

Grants Module – Detailed Working

Implementation Overview

Grant functionality is handled primarily via app/Http/Controllers/Admin/GrantController.php, app/Http/Controllers/GrantController.php, and related views under resources/views/admin/grants and resources/views/grants. Scoring logic is delegated to app/Services/ScoringService.php and workflows to app/Services/WorkflowService.php.

Area Status Details
Faculty grant submission Completed Faculty can submit grant records with metadata, amounts, dates, and evidence files. Routes are protected so that only authenticated faculty can create/update their own grants.
Admin grant review & approval Completed Admin screens show grant queues by status (pending, under review, approved, returned). Actions to approve, reject, or return to faculty are exposed through the admin grant controller, which internally calls the workflow service.
Grant scoring & caps Completed ScoringService calculates scores for grants using policy‑driven rules (category weights, maximum points per period, and aggregation with publications/RTN/bonus).
Evidence & file handling Completed Grant records can attach evidence documents. FileUploadService validates file size/type, stores files, and links them via the evidence tables in the database.

RTN & Bonus Recognition – Detailed Working

Implementation Overview

RTN submissions and bonus recognitions are managed via app/Http/Controllers/Admin/RtnSubmissionController.php, app/Http/Controllers/Admin/BonusRecognitionController.php, their public/faculty counterparts, and views under resources/views/rtn-submissions and resources/views/bonus-recognitions. Both modules share the same scoring and workflow engine as grants and publications.

Flow Status Details
Faculty RTN submission Completed Faculty can submit RTN activities with structured metadata and attach supporting files. Submissions are created in a Draft state and then sent into the workflow for review.
Faculty bonus submission Completed Bonus recognition requests (awards, distinctions, etc.) are captured through dedicated forms. Data is normalized so that bonus items can be scored and reported consistently alongside publications and grants.
Admin RTN & bonus review Completed Admin views provide filters by department, faculty member, and academic year. From the detail screens, approvers can approve, reject, or return items with comments, using the shared workflow actions.
RTN & bonus scoring Completed ScoringService computes points for RTN and bonus items according to policy rules (e.g., activity type, level, and caps). Scores feed into overall faculty performance and reporting summaries.

Workflow Changes

Unified Workflow Model

The approval engine is centered on workflow entities and is coordinated by app/Http/Controllers/Admin/WorkflowController.php and app/Services/WorkflowService.php. Recent changes ensure that publications, grants, RTN, and bonus items all use a single, consistent workflow model with shared states and transitions.

Area Status Details
Standardized workflow states Completed All modules now share a common set of states (Draft, Submitted, Under Review, Approved, Returned, Rejected), which simplifies both UI and reporting logic.
Role‑based transitions Completed Transition rules are enforced so that only authorized roles (faculty, HoD, Dean, central admin) can move items between specific states. Routes and middleware have been aligned with these rules.
Comments & return reasons Completed When items are returned or rejected, approvers must supply comments. These comments are stored with the workflow step and surfaced in faculty views, closing the feedback loop for grants, RTN, and bonus submissions.
Integration with scoring & reports Partially done Only Approved items are considered in scoring and reports. Integration is in place, but additional summary and analytics views will be added to the reporting dashboards.

Next Actions Specific to These Modules

  • Enhance analytics dashboards to show separate and combined trends for grants, RTN, and bonus recognitions.
  • Add more granular validation rules and user‑friendly error messages on all submission forms.
  • Expand automated test coverage for grant/RTN/bonus workflow transitions and scoring edge cases.
